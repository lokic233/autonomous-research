## PART B — NEW thesis candidates

### NEW-T1: `fork()` + CoW as a first-class GPU memory primitive for branchy agent decoding (vAttention is read-only; this is the write-after-fork path)
- Repo / evidence basis: Metric 5b (28-layer Qwen2.5-7B real autoregressive decode, 448 CoW events, bit-identical, peak HBM 1120 vs 2016 MiB), Metric 5c (TOT rollback fires CoW exactly once, 1 page copied, siblings uncorrupted), Metric 3 (≈0% attn overhead).
- Contribution type: runtime primitive
- Closest prior: vAttention (read-only sharing) and ChunkAttention (no write-after-fork). Outside it because the contribution is the SEMANTIC operation `fork → divergent writes → CoW` while preserving contiguous VA so unmodified kernels keep running — a property no software prefix-sharing system can offer (PagedAttention is mandatory for vLLM/SGLang).
- Closest OSS competitor: vLLM APC. Does not invalidate because APC mandates PagedAttention kernels; the contribution here is that fork+CoW does NOT require kernel rewriting.
- Anti-FlashInfer: YES — FlashInfer is a kernel package; this is a memory abstraction that lets FlashInfer run unchanged on shared physical pages.
- No-Code test: the abstraction "branchable KV state with contiguous-VA preservation and CoW on first divergent write" remains as a named primitive even if the H100 code is deleted.
- Baseline-death: vLLM-APC software baseline. Brief's own retraction: software is ~700× faster on fork latency and ~6× larger at 32-block prefix → must reframe around correctness/kernel-compatibility, not headline speed.
- Highest-EV experiment: K∈{8,16,32} branch TOT/MCTS with stochastic decoding, comparing bit-identical reproducibility and end-to-end throughput between HW-CoW (unmodified FlashAttention) and vLLM-APC (PagedAttention kernel). Cost: ~1 week H100. Min success: ≥1.2× throughput on workload where APC's PagedAttention kernel overhead dominates. What it kills: "software CoW is universally sufficient."
- 30-day test: YES (mechanism already runs, evaluation framework exists in repo).
- Venue: ASPLOS
- Vote: **YELLOW** — survives vAttention but B8's vLLM-APC 700× number is a loaded gun; can only flip GREEN with a kernel-compatibility-driven workload win.

### NEW-T2: Cross-domain CoW for heterogeneous agent state (KV + RNG + tool-log + retrieval cache) with per-domain page granularity
- Repo / evidence basis: ASPLOS debate consensus in repo 3 ("Cross-domain CoW policy ... heterogeneous page granularity ... the genuinely-new architectural angle"); forkedkv mechanism (CUDA VMM cuMemCreate/Map/Unmap) generalizes beyond KV; Metric 5c demonstrates branch isolation guarantees.
- Contribution type: abstraction
- Closest prior: CXLfork (ASPLOS'25, CPU-only, uniform page); vAttention (KV-only). Outside both because the contribution is a UNIFIED fork policy across state types with different page sizes (2MB KV vs 4KB RNG vs variable-length tool log) and different determinism semantics.
- Closest OSS competitor: ad-hoc per-system checkpointing (none unify). Does not invalidate because no system today provides a single fork() across agent state types.
- Anti-FlashInfer: YES (orthogonal to kernels).
- No-Code test: the abstraction — "agent state is a heterogeneous CoW arena" — and the page-granularity policy survive without the H100 implementation.
- Baseline-death: a reviewer who says "you only built KV; the rest is hand-waving." This is the real risk.
- Highest-EV experiment: implement RNG-state CoW + retrieval-cache CoW on the existing forkedkv VMM, run a stochastic multi-rollout agent (Claude Code-style tool use), measure bit-identical reproducibility AND capacity gain across all three. Cost: ~3 weeks. Min success: bit-identical rollouts across ≥3 state types with combined memory savings ≥40% on a real agent trace.
- 30-day test: YES (tight — KV is done, RNG is ~1 week, retrieval ~1 week, eval ~1 week).
- Venue: ASPLOS
- Vote: **YELLOW** — strongest framing on paper, weakest evidence today (only KV is actually built).

### NEW-T3: 93% of GPU CoW cost is driver metadata, not data movement — the cuMemMap critical-path characterization
- Repo / evidence basis: forkedkv CoW cost decomposition: ~178µs/page total, 13µs D2D copy (7%). Lab 1 ceiling is driver-internal at cuMemSetAccess, not at VMA count.
- Contribution type: characterization
- Closest prior: vAttention measures end-to-end overhead but does NOT decompose the cuMemMap path. No published number isolates the driver-metadata cost of CUDA VMM operations.
- Closest OSS competitor: NVIDIA's own profiling tools (nsys/ncu) but no one has published this decomposition for the agentic CoW use case.
- Anti-FlashInfer: YES.
- No-Code test: the 93%-driver / 7%-data number is the result.
- Baseline-death: NVIDIA could ship a batched cuMemMap API tomorrow and obsolete the finding.
- Highest-EV experiment: batched-remap proof-of-concept (multiple pages per single ioctl) measuring amortized per-page cost. Cost: 1 week. Min success: ≥5× reduction with batching. What it kills: the implicit assumption (vAttention, ChunkAttention) that HW remap is intrinsically expensive — locates the cost in a specific API surface.
- 30-day test: YES.
- Venue: MLSys (characterization-friendly) or workshop.
- Vote: **YELLOW** — risk of "section, not paper" like T2.

### NEW-T4: Agent prefix invalidation is a superlinear cache pathology in production engines — a workload taxonomy
- Repo / evidence basis: EDMM P1.3 — vLLM 1.38×(4K)→5.41×(32K), SGLang 1.61×→5.24×, superlinear in BOTH engines. EDMM standalone 4.18× penalty at 16K. vLLM live 8.21× at one realistic config.
- Contribution type: workload model
- Closest prior: existing prefix-cache analyses (Radix, PA) assume append-only suffixes. None has measured the mid-prompt invalidation pathology as a workload characteristic across engines.
- Closest OSS competitor: none — Radix/PA papers don't characterize their own failure regime.
- Anti-FlashInfer: YES (workload phenomenon, not kernel).
- No-Code test: the taxonomy of agent-induced invalidation patterns and the superlinearity claim remain.
- Baseline-death: a follow-up paper that demonstrates a cheap incremental-hash fix → the pathology becomes "already solved."
- Highest-EV experiment: trace-driven measurement across ≥4 frameworks (Claude Code, AutoGPT, LangGraph, OpenAI Assistants) on vLLM + SGLang + TGI. Cost: 2 weeks. Min success: penalty ≥3× on ≥3 frameworks at 16K context. What it kills: the assumption that Radix/PA already solves agent caching.
- 30-day test: YES.
- Venue: MLSys or NeurIPS (Sys ML track).
- Vote: **YELLOW** — strong measurement story, but separable from the GPU mechanism work; could end up "interesting but small."

### NEW-T5: Contiguous-VA preservation has a quantified cost — the kernel-transparency Pareto frontier
- Repo / evidence basis: B8 — VA-swap CoW is 59% faster than contiguous-VA CoW but breaks contiguous addressing; scratch-pool only 3% faster (NULL result). Brief explicitly retracts the prior "47% removable" claim.
- Contribution type: characterization + abstraction (a frontier, not a point)
- Closest prior: vAttention implicitly claims contiguous-VA preservation is "free." This measures its cost.
- Closest OSS competitor: none.
- Anti-FlashInfer: YES.
- No-Code test: the 59% number and the Pareto frontier framing remain.
- Baseline-death: any future kernel that natively accepts non-contiguous addressing (PagedAttention is exactly that — but then vAttention's premise also collapses).
- Highest-EV experiment: a third design point (chunked-VA + sparse-aware kernel) measured against both endpoints, plus end-to-end perf on each. Cost: 3 weeks. Min success: a Pareto chart with ≥3 design points and a clear regime where each wins.
- 30-day test: YES (tight).
- Venue: MLSys or ASPLOS section.
- Vote: **YELLOW**.

## PART C — Top 3 NEW theses ranked + honest GREEN call

**Ranked priority:**
1. **NEW-T2** (cross-domain CoW with heterogeneous page granularity) — highest ceiling; named by 4-way consensus as the genuinely-new architectural angle; cleanly outside vAttention/ChunkAttention/CXLfork.
2. **NEW-T1** (fork+CoW as first-class GPU primitive for branchy decoding) — strongest evidence base today (Metric 5b/5c real measurements); lives or dies on framing-away-from-headline-speed.
3. **NEW-T4** (agent prefix invalidation as superlinear pathology) — cleanest standalone story, lowest risk of being killed by vAttention/ChunkAttention because it's a workload paper, not a mechanism paper.

**Which would I vote GREEN under hostile review?**

**NONE today.** Honest assessment:

- NEW-T2 has the right framing but the evidence is KV-only; until RNG + retrieval CoW are built and shown bit-identical on a real stochastic agent, a hostile reviewer will say "you renamed a 1-domain system as a multi-domain abstraction." It's the most likely to FLIP GREEN within 30 days if the cross-domain build lands.
- NEW-T1 is real-and-built but B8's own retraction (vLLM-APC 700× faster fork, 6× larger capacity) is a loaded gun the committee already documented against itself. The kernel-compatibility framing is correct but soft; needs a workload where unmodified-FlashAttention vs PagedAttention kernel perf gap is the headline.
- NEW-T4 is the safest paper but the smallest contribution — likely workshop or short MLSys, not ASPLOS.
- NEW-T3 and NEW-T5 are characterizations; both carry the "section not paper" risk that already YELLOW-ed T2.

**Conditional GREEN:** I would vote NEW-T2 GREEN *if* the cross-domain experiment (RNG + retrieval CoW, bit-identical multi-rollout) lands with a measured combined memory saving and reproduces a stochastic agent trace. That single experiment is the difference between "promising framing" and "defensible ASPLOS contribution."
