### CANDIDATE I
- **Vote: RED** (leaning YELLOW only if the gating experiment succeeds)
- **Gating experiment that would make it 6/6 GREEN:** Exhibit ≥1 *measured* configuration where VMM CoW is the throughput-optimal choice — i.e., populate the "iff TRUE" branch of the rule. Concretely: find a contiguous-VA-required kernel (a FlashInfer-class kernel that genuinely cannot run paged) at a prefix length and fanout < K/prefix_pages where measured VMM-CoW tokens/s beats BOTH software prefix-sharing AND the paged FlashInfer path. Report the win margin and the boundary fanout where it flips.
- **Fatal risk:** The decision rule's positive branch is *empty on your own measured evidence*. C* found **0/12 win-region**, with VMM CoW 1.06–2.20× slower than software and 41–152× slower than FlashInfer. If there is no measured config where the "use VMM CoW" branch fires, the procedure collapses to "always use software" — which is C* restated with A*'s K/prefix_pages bound bolted on as decoration. The reviewers are *correct*: it's A*+C* stapled. A decision procedure whose TRUE-branch is measure-zero is not a discovery; it's a corollary. This is the same trap that killed E (everything reduces to software-equivalence).

### CANDIDATE J
- **Vote: YELLOW** (the only candidate with a structural moat against software-equivalence, but the attestation chain is unproven)
- **Gating experiment that would make it 6/6 GREEN:** The **adversarial negative control**, end-to-end. (1) Construct a malicious/buggy runtime that *actually physically aliases* two tenants' KV pages. (2) Show the driver-handle attestation **fails/detects it** (contaminated handle == sibling handle → proof rejects), while (3) software refcounting's self-report can be *forged to PASS* under the same aliasing. (4) Critically: bind the handle distinction into the GPU's signed CC attestation report (H100/H200 confidential-compute SPDM/device-attestation), and have a **remote verifier that trusts only the hardware root-of-trust, not the runtime** validate it. Pass = the verifier accepts genuine non-aliasing and rejects forged claims; SW cannot produce a report the remote verifier accepts.
- **Fatal risk:** That `cuMemRetainAllocationHandle`'s distinctness is only an **in-process userspace bookkeeping value**, not bound into the GPU's signed attestation report. If the comparison "contaminated handle ≠ sibling handle (all reps)" is performed by — or reported through — the *untrusted* runtime, then under J's own threat model (distrust runtime, trust driver) the proof is worthless: the untrusted runtime can simply lie about the comparison result. "SW structurally cannot emit it" becomes *true but useless* because HW's emission is also untrusted unless it is cryptographically rooted in the device. J is GREEN iff the handle distinction is signed by the hardware RoT and remotely verifiable; J is RED if it's just a local driver integer.

### YOUR-OWN
- **Thesis:** This is a *refinement* of J, not a competitor: **"Physical non-aliasing is the single residue in the entire A*/B*/C*/E corpus that is HW-structural rather than HW-faster."** E already proved SW matches HW bit-identically and beats it (fork 240× faster) on *every* axis except `driver_handle_proof` (structurally False for SW). C* proved HW *loses* on performance (0/12). So every performance-framed thesis (I, and any A*×B "capacity-cliff→recompute" composition) collapses into "software dominates / ceiling is escapable by the already-dominant software path" — the E-killing equivalence trap. The non-aliasing attestation is the *only* claim where SW is structurally incapable, not merely slower.
- **Vote: GREEN-conditional** — **why it beats I and J-as-originally-framed:** It beats I because I has no moat (software-equivalent, empty win-branch). It beats vanilla J by naming the exact load-bearing experiment (the forge-resistance negative control + hardware-RoT binding) instead of resting on "SW can't emit it," which is necessary but not sufficient. The contribution is sharpest stated as a *negative-plus-positive*: SW can fake every isolation property (E) **except** a hardware-rooted physical-disjointness proof — and here is the multi-tenant CC threat model where that one residue is decisive and forge-resistant.

### PICK
**CANDIDATE J** (in the hardened "forge-resistant, hardware-rooted attestation" framing above). It is the only candidate that survives the software-equivalence critique that killed E and guts I — because it rests on a *structural* HW capability, not a performance margin that C* already showed HW loses.

**Single experiment to run next:** The **adversarial negative control with remote verification** — inject real physical aliasing under a malicious runtime; prove the hardware-RoT-signed driver-handle attestation *rejects* it while a forged software refcount report *passes* a runtime-trusting verifier but *fails* the hardware-trusting verifier. If the driver handle proves bound to the GPU CC attestation report and forge-resistant → 6/6 GREEN. If the handle turns out to be a local userspace integer the untrusted runtime can fabricate → J dies exactly like E, and the committee ships with two greens.
